# Demo Riskleri ve Trade-off

## Demo Riskleri

Bir yazılım demosu sırasında çeşitli teknik problemler oluşabilir.

Örnek riskler:

- İnternet bağlantısının kesilmesi
- Backend servisinin çalışmaması
- Veritabanı bağlantısının kopması
- Port çakışması
- API isteğinin başarısız olması
- Frontend uygulamasının açılmaması
- Ortam değişkenlerinin yanlış yapılandırılması

Bu nedenle demo öncesinde sistemin tüm bileşenleri kontrol edilmelidir.

## Yedek Plan

Canlı demo başarısız olursa kullanılabilecek yedekler:

- Ekran görüntüleri
- Kısa demo videosu
- Terminal çıktıları
- API response örnekleri
- GitHub repository
- Teknik dokümantasyon

## Trade-off Nedir?

Trade-off, bir teknik karar alınırken bir avantaj elde etmek için başka bir konuda belirli bir dezavantajı kabul etmektir.

Örneğin:

Daha güçlü güvenlik kontrolleri sistemi daha güvenli hale getirirken işlem süresini artırabilir.

Cache kullanımı performansı artırabilir ancak eski verinin kısa süreliğine gösterilmesine neden olabilir.

Microservice mimarisi ölçeklenebilirliği artırabilir ancak sistem yönetimini daha karmaşık hale getirebilir.

Bu nedenle teknik kararlar yalnızca avantajlarına göre değil, oluşturabilecekleri dezavantajlarla birlikte değerlendirilmelidir.
